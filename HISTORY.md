# Build Policy version history

One row per policy version, newest first. The header of `BUILD-POLICY.md` must match the top row; `policy check` enforces that, uniqueness and ordering.

| Version | Date | Changes |
|---|---|---|
| 2.64 | 2026-10-09 | The pre-commit secret scan reads the staged diff. The history scan (`betterleaks git .`) sees every commit except the one being made, so a staged key passed the hook and was caught one commit later. New required script `secrets:staged` (`betterleaks git --staged --redact`) runs in `gates --fast`, which fails outright when the script is missing rather than skipping the gate; the full run keeps the history scan. Both scans drop `-v` (verbose in betterleaks 1.x, which prints the value; `--validate` in betterleaks 2, which sends the finding to the provider) and add `--redact`; `check` FAILs a secrets script with a leaky flag or without `--redact`. A failed scan prints each finding as `file:line (rule)` with the value redacted, since betterleaks 1.x otherwise reports only a count. |
| 2.63 | 2026-10-09 | Registry model tiers move to Claude Sonnet 5.5 (`claude-sonnet-5-5`) and Claude Haiku 5.5 (`claude-haiku-5-5`), verified against the official pricing page. `check` treats Haiku 5.5 as a thinks-by-default model (a first-block read FAILs beside it), FAILs a `temperature`/`top_p`/`top_k` request field beside a 5.5-generation, Fable or Mythos model (a 400 there; WARN elsewhere), and names the registry tiers in its messages instead of a hardcoded model. project-standards gains the sampling-parameter and `max_tokens` headroom rules. |
| 2.62 | 2026-10-06 | Test DMGs are not releases. Four rules (version freeze in `check`, `verify-ready` and the Stop hook; the update-banner requirement) treated any DMG in `release/` as a shipped copy, so an app under `"distribution": "none"` was told to bump, tag and add a banner after every test build. `shippedDmgVersions` returns nothing under `none`; the rules switch on when the project declares a real distribution. A declared-store app without an update check now FAILs `check` before its first DMG rather than after the launch build. Regression test added. |
| 2.61 | 2026-10-06 | The enforcement code is gated like an app: `tests/policy.test.js` covers the hook predicates and runs from `check`; a change to `scripts/`, `machine/` or `templates/` FAILs `check` without a `security-ack`; the policy CHANGELOG must head its entries with the current version. New `check --all` prints a compliance table for every project and `sync-templates` rewrites the drift-checked files for one project. `deps:check` enforces the allowlist re-verification window. `check` FAILs `thinking: {type: 'disabled'}` beside a model that rejects it (Sonnet 5.5, Opus 5.5, Fable, Mythos). Standards text updated to the 2.58 supply-chain model throughout (no Socket wrapper, `min-release-age=2`, one score per new package), the CSRF section now matches § Network Exposure, and the command table lists every command. Version history moved to HISTORY.md so BUILD-POLICY.md reads in one sitting; `check` and `mirror` read it there. |
| 2.60 | 2026-10-05 | Private-only update: guidance kept in the private copy of the policy. No change to the public standards or enforcement. |
| 2.59 | 2026-10-03 | Advisory exceptions are drafted by the AI and approved by the developer: the AI may write `audit-exceptions.json`, and `policy approve-exception <GHSA-id>`, which only the developer runs, prints the entry and records an approval bound to its content in `audit-approvals.json`. The gates and the CI audit step honour only approved, unchanged, unexpired entries, and `check` fails an unapproved one. The claim hook reads heredocs: a body fed to `cat > file` is judged by its redirect target, and a script fed to an interpreter by the path literals it quotes, so prose that mentions build-policy no longer blocks an app session editing its own files. A repository's first commit can pass the review gate: with no earlier commit to compare against, the gates review it from an empty base in a scratch copy. |
| 2.58 | 2026-10-03 | The Socket npm install wrapper is retired; installs use npm directly. It looked up the whole tree on every install against an hourly quota, so large first installs failed, and its bundled resolver pruned optional dependencies from lockfiles. Every install is now covered by `min-release-age=2`, `npm audit`, and `npm audit signatures` in full gates. Socket scores only packages new to a project (`verify-package.js` records the score in the allowlist entry, and `deps:check` refuses a new entry without one or a developer-written waiver, which the AI may not write) and allowlisted packages with a risk signal, which `health` lists. `doctor` checks the release age and that the wrapper is off. A score is judged on the package's own scores and on critical or high alerts anywhere in its dependencies; the with-dependencies aggregate is recorded, not judged. A flagged package that is accepted needs a recorded decision with a reason. Full gates FAIL on a package that runs code at install time unless it is recorded with a reason, and `scaffold` records the existing set as a baseline. A high or critical advisory with no fixed release can be carried under a dated, developer-written exception in `audit-exceptions.json` (at most 90 days), honoured per advisory and package by the `security` gate and the CI audit step; `check` rejects malformed or expired entries and `health` fails once a fix exists. An urgent fix younger than the release-age quarantine is installed by the developer with a one-off override, which the AI may not run. |
